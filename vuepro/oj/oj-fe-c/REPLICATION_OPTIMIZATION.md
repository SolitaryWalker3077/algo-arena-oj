## 4. 接口状态与预览策略

### 当前后端已实现并直接使用

- `POST /user/sendCode`
- `POST /user/code/login`
- `DELETE /user/logout`
- `GET /user/info`
- `GET /question/semiLogin/list`
- `GET /exam/semiLogin/redis/list`
- `POST /user/exam/enter`
- `GET /user/exam/list`

### 后端尚未实现，前端已完成界面与接入层

- 题目热榜、题目详情、前后题、竞赛首题
- 代码提交与评测结果轮询
- 竞赛排行榜
- 用户详细资料、资料编辑、头像更新
- 消息列表与删除

所有未完成接口统一由 `src/utils/previewFallback.js` 降级到 `src/data/demoData.js`。接口上线后只需保持 API 层约定的数据结构，页面会自动退出预览态，无需删除页面内的散落 Mock 判断。

预览降级有以下边界：

- 登录失效（业务码 `3001`）继续清理登录态并跳转登录；
- `AbortController` 主动取消不会触发演示数据，避免旧请求覆盖新筛选结果；
- 普通网络错误、404/501 和未部署服务才使用界面预览数据；
- 资料和消息在预览态的修改只影响当前页面，不伪造成服务端写入成功。

## 5. 代码组织与质量提升

### 分层

- `src/apis/`：只描述 HTTP 接口、参数和取消信号；
- `src/data/demoData.js`：集中维护未完成接口的演示数据；
- `src/utils/previewFallback.js`：控制真实请求与预览降级边界；
- `src/utils/question.js`：集中处理后端字段兼容、难度文案和题库筛选；
- `src/components/`：抽取页面标题、预览提示、难度选择器和代码编辑器；
- `src/views/`：只负责页面状态和交互编排。

### 具体改进

- 移除空白首页和竞赛去向占位页，避免无效路由与重复页面；
- 使用路由级动态导入，题库、答题、消息、资料、排名互不阻塞首屏；
- 请求层区分业务错误、认证错误、HTTP 错误、超时和主动取消；
- 所有列表使用稳定业务主键，避免以数组下标作为渲染身份；
- 表单增加必填、手机号、邮箱和头像大小校验；
- 删除操作增加二次确认，提交按钮增加防重复状态；
- 题目内容以纯文本渲染，避免原实现直接 `v-html` 带来的 XSS 风险；
- 组件补充语义标签、ARIA 文案、键盘焦点样式和空状态；
- 修复后端字段为 `difficult`、参考前端字段为 `difficulty` 的兼容问题；
- 保留目标项目已有的题库参数规范化测试，并增加请求降级和题目摘要测试，总测试数由 14 增加到 20。

### 与原始参考代码对比

参考项目未声明 `.scss` 所需的 `sass` 依赖，直接执行 `npm ci && npm run build` 会失败。为获取可比数据，临时使用 `npm install --no-save sass@1.77.8` 后构建；该操作没有修改参考项目的依赖声明。

| 指标 | 参考代码 | 改造后 |
| --- | ---: | ---: |
| 生产构建耗时 | 8.23 s | 1.53 s |
| 入口命名 chunk gzip | 299.16 KB | 13.08 KB |
| 答题页命名 chunk gzip | 130.84 KB | 5.34 KB |
| 超过 500 KB 的 chunk 警告 | 1 | 0 |

命名 chunk 仅用于观察代码拆分效果，不等同于单个页面的完整网络传输量；改造后依赖被拆入共享 chunk。答题页不再引入体积较大的 Ace 构建，而使用满足当前 Java 单语言需求的轻量编辑器，因此答题页面自身 chunk 明显下降。未来需要多语言语法高亮时，可将 Monaco/Ace 作为仅答题路由加载的异步依赖。

### 运行时策略

- 竞赛列表保留 60 秒缓存、同请求合并与失败时陈旧缓存回退；
- 列表筛选和路由切换使用 `AbortController` 取消过期请求；
- 图片保留原生懒加载和异步解码；
- 页面与组件按路由拆分，未访问模块不参与首屏执行；
- 移除未引用 CSS 背景和两个无效页面组件；
- 代码编辑器按当前业务只支持 Java，避免加载未使用语言包。

## 9. 后端接口完成后的接入顺序

1. 优先完成题目详情、竞赛首题、前后题，答题工作台即可加载真实题面；
2. 接入代码提交与结果查询，保持 `pass=3` 表示处理中即可复用现有轮询；
3. 接入个人资料与消息接口，页面会自动取消预览提示；
4. 接入排行接口，返回 `rows`，字段可使用 `rank/userId/nickName/solved/score/penalty`；
5. 后端字段若与约定不同，只在 `src/apis/` 或相应 normalize 函数中映射，不直接修改视图组件。

建议接口完成后补充 Playwright 端到端用例，覆盖真实登录、头像上传、代码评测状态流转和消息删除持久化。
